# Project Plan

## Project Goal

Build a notebook-based analytical system to investigate e-commerce funnel friction and unusual engagement patterns.

## Unit of Analysis

The primary unit is a user session.

Each session contains an ordered sequence of behavioral events.

## Event Schema

Each event should contain:

* event_id
* user_id
* session_id
* event_timestamp
* event_name
* page_name
* product_id
* click_count
* duration_seconds
* error_type
* payment_status
* navigation_action

Session context is also recorded on each event:

* device_type
* acquisition_channel

Synthetic scenario and ground-truth fields are stored in `sessions.csv`, not repeated on every event row.

## Event Types

Core journey events:

* homepage_view
* search
* product_view
* add_to_cart
* cart_view
* remove_from_cart
* checkout_start
* payment_attempt
* purchase

Additional behavioral events:

* click
* back_navigation
* page_error
* payment_failure
* payment_success
* session_exit

## Analysis Workflow

### 1. Data Generation and Loading

Load the supplied event-level data.

Treat all supplied records as synthetic and preserve the session-level scenario labels for evaluation only.

### 2. Data Quality

Check:

* Missing values
* Duplicate events
* Invalid timestamps
* Invalid session sequences
* Negative durations
* Unexpected event types

### 3. Exploratory Data Analysis

Analyze:

* Event frequency
* Session length
* Session duration
* Funnel progression
* Purchase outcomes
* Event timing distributions

### 4. Funnel Analysis

Calculate stage-to-stage conversion and abandonment.

Identify the stages with the largest absolute and relative drop-offs.

### 5. Friction Detection

Create transparent behavioral indicators for:

* Repeated clicks
* Payment failures
* Back navigation
* Long page duration
* Technical errors
* Repeated checkout attempts

### 6. Feature Engineering

Aggregate events into session-level features.

Examples:

* total_events
* session_duration
* repeated_click_count
* back_navigation_count
* payment_failure_count
* error_count
* checkout_duration
* product_views
* cart_additions
* unique_pages
* median_event_interval
* event_rate_per_minute

### 7. Anomaly Detection

Apply Isolation Forest to selected session-level behavioral features.

Compare model flags with known synthetic anomaly labels.

### 8. Evaluation

Use:

* Precision
* Recall
* F1-score
* Confusion matrix
* Anomaly score distributions

Evaluate separately for synthetic anomalies and real unlabeled data.

### 9. Product Recommendations

Translate observed friction patterns into product improvement hypotheses.

Prioritize recommendations using affected sessions, severity, and business relevance.

## Expected Outputs

1. Data cleaning and EDA notebook
2. Funnel analysis notebook and conversion table
3. Friction analysis notebook and hotspot table
4. Session-level feature dataset
5. Anomaly detection notebook and evaluation metrics
6. Product recommendations and limitations in each analytical notebook

## Notebook Execution Order

1. `notebooks/01_data_cleaning_eda.ipynb`
2. `notebooks/02_funnel_analysis.ipynb`
3. `notebooks/03_friction_analysis.ipynb`
4. `notebooks/04_anomaly_detection.ipynb`

The first three notebooks load the raw data independently. The final notebook uses the session feature table generated by Notebook 03.

## Constraints

* Notebook-first implementation
* No unnecessary infrastructure
* No deep learning
* No unverified fraud claims
* Reproducible random seed
* Clear markdown explanations throughout the notebook
